# 运行频率、token 与服务器负载

客户端代码以已发布的 `0.7.11` 为基准。线上负载是 2026-10-19 的短时观察，不表示容量上限或长期稳定性认证。

## 客户端调用频率

`worlds.terrarium.tickIntervalMs` 默认 60,000 ms，可配置范围 10,000–3,600,000 ms。每次后台检查完成后等待该间隔再检查；以下按默认配置、网络正常、箱子已认领计算，不包含启动、重连和手动操作。

| 操作 | 一个盒子 | 同一部署的地、水两个盒子 | 调用模型 |
|---|---|---|---|
| 本地地箱模拟 | 每 10 秒推进；普通虫子每分钟行动，蚂蚁每 10 秒行动 | 地箱同左，水箱每次后台检查推进 | 不调用 |
| 状态保存及 WS 上报 | 约 1 次/分钟，最多约 1,440 次/天 | 约 2 次/分钟，最多约 2,880 次/天 | 不调用 |
| 排名检查（提醒开启时） | 约 1 次 GET/分钟 | 约 2 次 GET/分钟 | 请求本身不调用 |
| 公告检查 | 约 1 次 GET/分钟 | 约 2 次 GET/分钟 | 请求本身不调用 |
| WS 心跳 | 每条连接每 30 秒收到 ping 并回复 pong | 两条连接，各自执行 | 不调用 |

两个盒子的常态后台流量约为每分钟 2 条状态消息、4 次 HTTP GET，另有心跳。未认领时仅检查公共公告，不自动认领或上报。关闭排名提醒会停止该盒子的后台排名查询；排行榜服务地址留空会关闭远程上报、排名和公告检查。

认领会注册并保存凭据；已有 ID/token 随后复用。修改状态的工具或面板操作会额外保存并上报一次；`terrarium_sync` 额外完整上报。查看、历史、回放和面板定时读取不会保存或上报。显式读取排行榜、提交反馈分别额外发起查询、提交请求。手动工具调用不受后台间隔限制。WS 连接或确认失败最多重试一次；失败后由后续检查继续尝试，没有连续无限重试循环。完整/增量模式均使用相同后台间隔。

World 不直接调用 LLM。生态变化、名次下降和新公告通过事件交给宿主；是否唤醒模型、如何合并事件、后续调用几轮由 Core、Persona 和部署配置决定。地箱昼夜事件使用 `piggyback`，其他生态事件和公告使用 `debounce`。一次 10 秒模拟步进不等于一次 LLM 请求，也不存在固定的“每小时必须照料次数”。

## 每次输入、输出 token

自动模拟、状态上报、排名及公告的网络请求本身消耗 **0 个 LLM token**。它们返回 JSON 或产生事件，只有相应内容被交给模型时才计入模型上下文。

以下使用 `js-tiktoken 1.0.21` 的 `cl100k_base` 对内容单独计数。它是可复核的参考编码，不代表任意 provider 的计费规则。工具调用侧计数的是紧凑 JSON `{name,arguments}`；回执侧计数的是实际工具返回字符串。未包含 provider 消息封装、其他 World、Persona、历史、思维链和自由文本输出。

| 固定内容 | 参考 token |
|---|---:|
| `src/ENV_PROMPT.md` | 4,309 |
| 25 个工具的 `name/description/parameters` 紧凑 JSON | 2,780 |
| 上述内容合并 | 7,089 |

这些内容在宿主把它们放入请求时占用输入上下文；是否缓存、是否逐次发送以及缓存如何计费由宿主和 provider 决定。

| 单次操作样本 | 模型输出：工具调用 JSON | 模型后续输入：工具回执 |
|---|---:|---:|
| 查看未认领状态 | 12 | 58 |
| 认领地箱或水箱 | 14 | 27 |
| 查看新认领的地箱 | 15 | 993 |
| 查看新认领的水箱 | 15 | 171 |
| 全箱 25 格浇水 | 30 | 535 |
| 单格浇水 | 17 | 24 |

| 放入一只蚂蚁 | 22 | 30 |
| 查看单格历史（仅一条小时样本） | 17 | 27 |
| 查看水箱历史（仅一条小时样本） | 12 | 27 |
| 关闭排名提醒 | 16 | 10 |
| 读取一次捕食的三帧回放 | 28 | 1,865 |
| 实际部署：排行榜查询 | 19 | 270 |

前 12 项由真实 World 类在本地临时部署中执行，固定时间，关闭远程上报，不启动 bot、不调用模型；数字包含该样本的回执状态。最后两项取自实际部署日志，仅公开计数，不公开用户内容。它们都是样本，不能作为工具的固定大小或最大值；生物、巢穴、历史、榜单条数、名称及回放场景都会改变回执大小。回放按需读取，日常 inspect 不返回完整历史或回放帧。

2026-10-19 01:52:53–02:52:53（UTC+8）的一个实际部署记录到 2 次生态箱工具调用（排行榜、反馈各一次）和 1 条生态箱公告事件；这条事件正文为 289 个参考 token。这个较安静的一小时不代表所有游戏状态，不能据此推算忙碌场景的模型调用上限。

同一窗口的 96 条宿主 usage 记录均未获得有效的输入/输出计数，记录值为 0，因此目前无法提供真实完整请求的计费 token。这个 0 不代表模型免费或实际没有消耗。完整请求还包含其他上下文，完整输出还可能包含思维链、文本及多个工具调用；上述表格只报告生态箱提供或接收的内容大小。

## 线上服务器负载

采样窗口：**2026-10-19 02:52:52–02:53:52（UTC+8）**，实际 60.02 秒，每 5 秒读取一次，共 13 个点。服务在正常业务流量下运行；没有额外压测或向用户盒子提交测试状态。

| 指标 | 实测值 |
|---|---:|
| 主机逻辑 CPU / 总内存 | 1 / 6.75 GiB |
| 主机可用内存（窗口结束） | 3.91 GiB |
| 已有地、水盒子合计 | 18 |
| 服务进程平均 CPU，100% 表示占满一个核 | **0.217%** |
| 服务进程 RSS 最小 / 平均 / 最大 | **93.62 / 94.21 / 94.53 MiB** |
| 主机平均 CPU 活跃比例 | 2.72% |
| 主机窗口结束 load average（1/5/15 分钟） | 0.064 / 0.140 / 0.104 |
| 后端端口已建立 TCP 连接数范围 | 10–12 |
| 单个盒子状态紧凑 UTF-8 JSON 最小 / 中位 / 最大 | 994 / 15,431.5 / 151,825 字节 |
| 全部排行榜持久化文件 | 471,701 字节 |

进程 CPU 根据 `/proc/<pid>/stat` 的 user+system tick 差值除以实际墙钟时间计算；RSS 来自 `/proc/<pid>/status`。主机 CPU 读取 `/proc/stat`，活跃比例不含 idle 和 iowait；主机指标包含其他服务。18 个盒子是已保存状态的条目数，不表示 18 个客户端同时活跃。连接数包括后端 HTTP 和 WS 连接，不等同于在线用户数。状态大小不含 WS 协议封装、TLS 和心跳，也不是模型 token。

服务按序写入排行榜 JSON，每次接受上报都会重写文件；规模增长会增加序列化和磁盘写入成本。当前采样仅说明此时 18 个盒子的负载，未测最大并发、峰值延迟、事件暴增场景或长期增长。服务器不调用模型，不承担客户端的游戏模拟；它负责身份、状态校验及保存、排行榜、公告、反馈和公共展示。
